llama.vim                                                                *llama*

LLM-based text completion using llama.cpp

================================================================================
Requirement

Requires:

- neovim or vim 9.1+
- curl
- llama.cpp server instance
- FIM-compatible model
- Instruct-compatible model

================================================================================
Default Shortcut

- Tab         - accept the current suggestion
- Shift+Tab   - accept just the first line of the suggestion
- <leader>ll] - accept just the first word of the suggestion
- <C-J>       - cycle to next completion (when multiple are available)
- <C-K>       - cycle to previous completion (when multiple are available)
- <leader>llf - trigger FIM completion manually
- <leader>lli - trigger instruction-based editing (instruct mode)
- <leader>llr - rerun the instruction
- <leader>llc - continue the instruction
- <leader>llr - accept the instruction (accept the instruction)
- <leader>llq - cancel the instruction (cancel the instruction)
- <leader>lld - toggle the debug pane

================================================================================
Commands

*:LlamaDisable*

		Disable the related autocommands and keymap for this vim/nvim session.
		Equivalent to vimscript function: `llama#disable()`

*:LlamaEnable*

		Enable the related autocommands and keymap for this vim/nvim session
		Equivalent to vimscript function: `llama#enable()`

*:LlamaToggle*

		Toggle the related autocommands and keymap for this vim/nvim session
		Equivalent to vimscript function: `llama#toggle()`

*:LlamaToggleAutoFim*

		Toggle autofim for this vim/nvim session
		Equivalent to vimscript function: `llama#toggle_auto_fim()`

*:LlamaInstruct*
		Trigger instruction-based editing (instruct mode) on selected text

*:LlamaDebugClear*
		Clear the debug pane logs.
		Equivalent to vimscript function: `debug#clear()`

*:LlamaDebugToggle*
		Toggle the debug pane.
		Equivalent to vimscript function: `debug#toggle()`

*:LlamaDebugSnapshot*
		Show a summary of the last exact FIM request in the debug pane.
		Use :LlamaDebugSnapshot! to include the full untruncated JSON snapshot.
		Equivalent to vimscript function: `llama#debug_show_snapshot()`

*:LlamaDebugSnapshotClear*
		Release the retained FIM request snapshot immediately.
		Equivalent to vimscript function: `llama#debug_snapshot_clear()`

================================================================================
How to start the server

Start the llama.cpp server with a FIM-compatible model. For example:

>sh
		$ llama-server \
				-m {model.gguf} --port 8012 -ngl 99 -fa -dt 0.1 \
				--ubatch-size 512 --batch-size 1024 \
				--ctx-size 0 --cache-reuse 256
<
`--batch-size` [512, model max context]

Adjust the batch size to control how much of the provided local context will
be used during the inference lower values will use smaller part of the context
around the cursor, which will result in faster processing.

`--ubatch-size` [64, 2048]

Chunks the batch into smaller chunks for faster processing depends on the
specific hardware. Use llama-bench to profile and determine the best size.

`--ctx-size` [1024, model max context], 0 - use model max context

The maximum amount of context that the server will use. Ideally, this should
be the same as the model's max context size, but if your device does not have
enough memory to handle the full context, you can try to reduce this value.

`--cache-reuse` (ge:llama_config.n_predict, 1024]

This should be either 0 (disabled) or strictly larger than
g:llama_config.n_predict using non-zero value enables context reuse on the
server side which dramatically improves the performance at large contexts. A
value of 256 should be good for all cases.

Configuration													*llama_config*

To customize the behaviour of `llama.vim`, you can set/modify the `g:llama_config`
variable.

Currently the default config is:
>vim
		let s:default_config = {
		    \ 'endpoint_fim':           'http://127.0.0.1:8012/infill',
		    \ 'endpoint_inst':          'http://127.0.0.1:8012/v1/chat/completions',
		    \ 'model_fim':              '',
		    \ 'model_inst':             '',
		    \ 'api_key':                '',
		    \ 'n_prefix':               256,
		    \ 'n_suffix':               64,
		    \ 'n_predict':              128,
		    \ 'n_cmpl':                 1,
		    \ 'stop_strings_fim':       [],
 			\ 'stop_strings_inst':      [],
		    \ 't_max_prompt_ms':        500,
		    \ 't_max_predict_ms':       1000,
		    \ 'show_info':              2,
		    \ 'auto_fim':               v:true,
		    \ 'max_line_suffix':        8,
		    \ 'max_cache_keys':         250,
		    \ 'context_providers':      [],
		    \ 'context_providers_enabled': v:true,
		    \ 'debug_snapshot_enabled': v:false,
		    \ 'debug_snapshot_callback': '',
		    \ 'fim_event_callback':     '',
		    \ 'ring_n_chunks':          16,
		    \ 'ring_chunk_size':        64,
		    \ 'ring_scope':             1024,
		    \ 'ring_update_ms':         1000,
		    \ 'keymap_fim_trigger':     "<leader>llf",
		    \ 'keymap_fim_accept_full': "<Tab>",
		    \ 'keymap_fim_accept_line': "<S-Tab>",
		    \ 'keymap_fim_accept_word': "<leader>ll]",
		    \ 'keymap_fim_next':        "<C-J>",
		    \ 'keymap_fim_prev':        "<C-K>",
		    \ 'keymap_inst_trigger':    "<leader>lli",
		    \ 'keymap_inst_rerun':      "<leader>llr",
		    \ 'keymap_inst_continue':   "<leader>llc",
		    \ 'keymap_inst_accept':     "<Tab>",
		    \ 'keymap_inst_cancel':     "<Esc>",
		    \ 'keymap_debug_toggle':    "<leader>lld",
		    \ 'enable_at_startup':      v:true,
		    \ }
<

- {endpoint_fim}		llama.cpp server endpoint for FIM completion

- {endpoint_inst}		llama.cpp server endpoint for instruction completion

- {api_key}				llama.cpp server api key (optional)

- {model_fim}			model name for FIM completion (optional)
						recommended: Qwen3 Coder 30B

- {model_inst}			model name for instruction completion (optional)
						recommended: gpt-oss-120b

- {n_prefix}			number of lines before the cursor location to include
						in the local prefix

- {n_suffix}			number of lines after  the cursor location to include
						in the local suffix

- {n_predict}			max number of tokens to predict

- {n_cmpl}			number of completions to cache per position (ring buffer).
					set to 2 or 3 for multiple options that you can cycle
					through with Ctrl-J/Ctrl-K. Each request generates this
					many completions (requires server with n_cmpl support).
					(default: 1)

- {stop_strings_fim}	return the result immediately as soon as any of these
						strings are encountered in the generated text for FIM completions

- {stop_strings_inst}	return the result immediately as soon as any of these
						strings are encountered in the generated text for instruction completions

- {t_max_prompt_ms}		max alloted time for the prompt processing
						(TODO: not yet supported)

- {t_max_predict_ms}	max alloted time for the prediction

- {show_info}			show extra info about the inference
						(0 - disabled, 1 - statusline, 2 - inline)

- {auto_fim}			trigger FIM completion automatically on cursor movement

- {max_line_suffix}		do not auto-trigger FIM completion if there are
						more than this number of characters to the right
						of the cursor

- {max_cache_keys}		max number of cached completions to keep in result_cache

- {context_providers}	list of synchronous providers that add extra context
						to FIM requests. Providers run in list order, so multiple
						providers can contribute to one request. A provider can be
						a function, or a dictionary with {provider}, optional {cond},
						and optional {name} entries. Functions receive a dictionary
						with {bufnr}, {filename}, {filetype}, {line} (1-based),
						and {column} (0-based byte column), and returns a list of
						`{'filename': string, 'text': string}` chunks. Invalid chunks
						and provider errors are skipped. Providers must return cached
						data immediately; do not wait for external services.

						Provider chunks are appended after ring context and are part
						of the FIM completion cache key.

						Example:
>vim
						function! MyContext(ctx) abort
						    if a:ctx.filetype !=# 'cpp'
						        return []
						    endif
						    return [{'filename': 'include/api.hpp', 'text': 'Result run(Context&);'}]
						endfunction

						let g:llama_config.context_providers = [function('MyContext')]
<
						A descriptor condition receives the same context dictionary.
						When it returns false, its provider is not called. Conditions
						are useful for configuration-specific routing; providers should
						still return an empty list when used outside their own scope.
>vim
						function! IsCpp(ctx) abort
						    return index(['c', 'cpp'], a:ctx.filetype) >= 0
						endfunction

						let g:llama_config.context_providers = [
						    \ {'name': 'clangd', 'cond': function('IsCpp'), 'provider': function('MyContext')},
						    \ function('AnotherContext'),
						    \ ]
<

- {context_providers_enabled}	whether to call context providers for FIM
						requests (v:true by default). Set this to v:false to
						disable every configured provider without changing its
						registration. Provider output is part of the FIM cache key,
						so toggling this setting will not reuse a completion made
						with different provider context.

						let g:llama_config.context_providers_enabled = v:false

						Use :LlamaToggleContextProviders to toggle the setting
						interactively. In Lua, reassign the modified configuration
						table so the value reaches Vimscript:
>lua
						local config = vim.g.llama_config
						config.context_providers_enabled = false
						vim.g.llama_config = config
<

- {debug_snapshot_enabled}	whether to retain the latest exact FIM request for
						manual `llama#debug_snapshot()` / `:LlamaDebugSnapshot`
						inspection. Disabled by default. Active callbacks enable capture
						for their own requests without changing this setting.

- {debug_snapshot_callback}	function or function-name string called with the
						exact, untruncated request snapshot for every FIM request.
						The snapshot includes the request body, local prefix/suffix,
						prompt, extra chunks, cursor and buffer metadata, and ring/provider
						statistics. It is disabled by default.

- {fim_event_callback}		function or function-name string called for versioned
						`request`, `response`, `shown`, `accepted`, `dismissed`, and
						`error` dictionaries. `request_id` correlates the lifecycle.
						Callbacks run from a zero-delay timer and receive deep copies;
						they should start asynchronous work rather than waiting for I/O.
						Callback errors are written to the debug log and do not stop FIM.
						When this callback, {debug_snapshot_callback}, and
						{debug_snapshot_enabled} are all disabled and no registered
						observers remain, request snapshots and lifecycle payload copies
						are not constructed. Cached responses retain only an internal
						scalar request ID so later display/acceptance stays correlated.

						In Neovim Lua, callbacks may be assigned directly:
>lua
						local config = vim.g.llama_config
						config.fim_event_callback = function(event)
						  vim.schedule(function()
						    require('my_monitor').record(event)
						  end)
						end
						vim.g.llama_config = config
<

						Independent integrations should register without replacing the
						single configured callback:
>vim
						let s:observer = llama#fim_observer_add(function('MyFimObserver'))
						" Later:
						call llama#fim_observer_remove(s:observer)
<
						`llama#fim_observer_has(id)` reports whether a handle remains
						registered. Subscriptions are event-scoped: an observer receives
						only lifecycle events dispatched while it is registered, so an
						observer added during an in-flight request can see a partial
						lifecycle while retaining the correct nonzero `request_id`.

						`llama#debug_snapshot()` returns a deep copy of the latest request
						without firing either callback. Once the matching response arrives,
						its `tokens_cached` value enriches the stored snapshot. Removing the
						last registered observer releases the snapshot when no other capture
						option is active. `llama#disable()` and
						`llama#debug_snapshot_clear()` also release it immediately.

- {enable_at_startup}	whether to enable llama.vim functionality at startup
						(v:true to enable, v:false to disable; default: v:true)

parameters for the ring-buffer with extra context:

- {ring_n_chunks}		max number of chunks to pass as extra context to the
						server (0 to disable)

- {ring_chunk_size}		max size of the chunks (in number of lines)
						Note: Adjust these numbers so that you don't overrun
						your context. At `ring_n_chunks = 64` and
						`ring_chunk_size = 64` you need ~32k context

- {ring_scope}			the range around the cursor position (in number of
						lines) for gathering chunks after FIM

- {ring_update_ms}		how often to process queued chunks in normal mode

keymaps parameters:

- {keymap_fim_trigger}		keymap to trigger the auto completion, default: <C-F>

- {keymap_fim_accept_full}	keymap to accept full suggestion, default: <Tab>

- {keymap_fim_accept_line}	keymap to accept a suggested line and move to the
					next line, default: <S-Tab>

- {keymap_fim_accept_word}	keymap to accept a suggested word. Accepting the
					last word moves to the next line only when the
					suggestion continues there, default: <C-B>

- {keymap_fim_next}		keymap to cycle to next completion, default: <C-J>

- {keymap_fim_prev}		keymap to cycle to previous completion, default: <C-K>

- {keymap_inst_trigger}		keymap to trigger instruction-based editing, default: null

- {keymap_debug_toggle}		keymap to toggle the debug pane, default: null

Example:

1. Disable the inline info (vimscript):
>vim
		" put before llama.vim loads
		let g:llama_config = { 'show_info': 0 }

2. Same but setting the specific variable directly
>vim
		let g:llama_config.show_info = v:false
<

3. Disable auto FIM completion, etc (lazy.nvim, lua):
>lua
		{
			'ggml-org/llama.vim',
			init = function()
				vim.g.llama_config = {
					n_prefix = 1024,
					n_suffix= 1024,
					auto_fim = false,
					keymap_fim_accept_full = "<C-S>",
					enable_at_startup = false,
				}
			end,
		}
<
4. Force single-line FIM completion (lazy.nvim, lua):
>lua
		{
			'ggml-org/llama.vim',
			init = function()
				vim.g.llama_config = {
					n_prefix = 1024,
					n_suffix = 1024,
					auto_fim = false,
					keymap_fim_accept_full = "<C-S>",
					stop_strings_fim = { "\n" },
					stop_strings_inst = { "\n" },
					enable_at_startup = false,
				}
			end,
		}
<
To adjust the colors for hint and info texts, `llama.vim` provides the
highlight group `llama_hl_fim_hint` and `llama_hl_fim_info`. You can modify these
groups using the normal way.

Example:

vimscript:
>vim
		highlight llama_hl_fim_hint guifg=#f8732e ctermfg=209
		highlight llama_hl_fim_info guifg=#50fa7b ctermfg=119
<
lua:
>lua
		vim.api.nvim_set_hl(0, "llama_hl_fim_hint", {fg = "#f8732e", ctermfg=209})
		vim.api.nvim_set_hl(0, "llama_hl_fim_info", {fg = "#50fa7b", ctermfg=119})
<
